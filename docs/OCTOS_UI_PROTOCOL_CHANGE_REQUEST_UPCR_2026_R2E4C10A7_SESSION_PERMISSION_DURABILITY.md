# UPCR-2026-R2E4C10A7 — Durable explicit Session permissions

- Status: Proposed, stacked on UPCR-2026-RC81B9296 (T-0625 ownership).
- Task: T-0626 / T-0621 F02.
- Methods: existing `permission/profile/set`, `permission/profile/list`, and `session/status/read`.
- Wire compatibility: no request or result field is added or removed. Durable storage and failure semantics change.

## Contract

1. Every successful SET persists the complete effective selection (`mode`, `network`, and explicit `approval_policy`/`inherit`) before updating process memory or returning success. This includes a selection equal to the current server default.
2. The versioned record is rooted at the authorized `ProfileRuntime.data_dir` (or the legacy top-level manager data dir), not a project-local sessions root. Its path, payload, cache, generation key, existence preflight, and runtime invalidation all bind the canonical `(profile_id, SessionKey)`; an omitted topic and explicit `#default` are one identity. Runtime cache entries retain their exact spelling, so SET invalidates and generation-fences both base and explicit-default forms. Sidecar components use bounded hash-suffixed names in a `~` namespace disjoint from every literal encoding only when the legacy encoding cannot fit the filesystem; every previously valid path remains unchanged, and deleting the literal form of a bounded stem cannot remove the long session's record. Project-local transcript routing may vary; permission identity does not.
3. Only a missing record is legacy and inherits the configured server default. Invalid JSON, missing/unknown fields, unsupported versions, invalid enum values, identity/path mismatch, and read/write I/O failures are not legacy.
4. Invalid records return `session_permission_invalid`; I/O failures return `session_permission_io` with a structured RPC error. Neither may fall back to wider defaults. Failed SET never returns an applied result and invalidates the cached runtime.
5. Permission records are lazily loaded before every SessionRuntime bootstrap and before LIST/SET/raw status reads. Background continuation uses the same effective-permission path. Once admitted, SET's complete write→anchor→runtime-invalidation operation is owned by a bounded application task (64 slots), not the cancellable RPC future. It retains the session mutation guard and finishes on success or failure even if the caller disconnects; capacity rejection happens before the first write. The RPC response still follows invalidation, and this does not retroactively cancel an already-running tool call. A cold read publishes only if its per-key permission generation is unchanged, so it cannot overwrite a completed SET, DELETE, or poison.
6. SET anchors the authoritative durable session record so a metadata-only session remains readable after restart. DELETE removes every permission sidecar in the authorized base/topic scope. The verified deletion scope is sufficient authority to unlink a corrupt doomed record without parsing it; ordinary reads remain fail-closed. Scope cleanup evicts matching cache entries and fences registered in-flight reads. Delegated gateway deletion performs this cleanup in the worker before reporting success, enumerating durable records independently of transcript existence so retries cannot resurrect a topic selection.
7. Persisted dangerous choices are revalidated against the current runtime/deployment mode during recovery; a record cannot bypass the current policy gate.

## Acceptance

The regression starts and stops the real `octos` binary twice against the same private data directory, in solo and non-solo modes, with no model calls. It covers read-only+network-deny+approval restoration, legacy defaults, write failure and poison, and corrupt/partial records. Storage units cover delete/recreate non-resurrection, canonical base/`#default` identity, bounded long base/topic sidecars with cold reload, literal-versus-hashed deletion disjointness, and stale cold-read rejection after SET/DELETE; real restart uses both default spellings. Runtime cache tests prove either default spelling invalidates both bootstrap generations and a downgrade rebuilds the alias with read-only sandbox policy while leaving other topics intact. A deterministic cancellation probe holds session persistence after the durable downgrade, cancels the RPC, and proves the application-owned worker retains the mutation guard, evicts the writable runtime, and rebuilds ReadOnly after release; a companion test proves the 64-task bound. A delegated-delete regression proves worker-side cleanup before success for base and topic records, including a retry with no topic transcripts and a truncated default record. The long raw-ID ownership fixture now performs authorized SET/LIST as well as cross-profile denial. T-0625 ownership and work-secret tests remain mandatory.
