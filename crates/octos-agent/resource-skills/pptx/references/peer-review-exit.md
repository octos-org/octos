# Peer 评审与退出

用于 PPTX 成品制作与返修。用户明确指定 solo、独立模型对照或仅查阅时，保留该范围，不暗加评审反馈。这里的模式是独立评审会话与持续制作 peer 协作；不是每页启动一个 worker，也不是把一次额外视觉 API 调用称为 peer。

## 开始时落实角色与运行状态

- **评审主会话**：保持简洁的目标、缺陷和验收上下文，只写协调记录与检查产物；不代改页稿、坐标或生图 prompt。
- **制作 peer**：独占源稿及交付物写入，复用已安装的 skill、builder、字体和 renderer，决定具体修法并自查。模型沿用用户选择。旧 writer 实际停止后才交接；已有有效内容、底图和检查不重做。
- **真实机制**：Octos 用 `peer_handoff`，按部署版本的 schema 调用 `peer_list` / `peer_gather` / `peer_send_input`；保存真实 peer 和会话标识。其他宿主使用有独立上下文和持续生命周期的等价会话能力；能力缺失时说明缺口，不悄悄降级为自己制作自己验收。
- **看图能力**：两个会话都必须收到实际图片内容。路径、OCR、制作方的文字结论不能替代直接看图。一次验证已知 PNG 传入即可，不每轮重做环境测试。
- **退出能力**：Octos 按 [证据接入](continuation-evidence.md) 绑定整稿制作 peer 的真实 session，记录 policy 检查结果；首个完整检查周期后核验 runtime 已消费该证据。缺少接线不允许被描述成“有阈值保护”。若宿主不支持内核观察器，明确只有协调者执行退出约定，没有硬性内核保障。

在已有制作记录里写下上述事实和用户已有的时间/费用预算，不另建项目专用 harness。初始化策略前确认任务/owner；同目录只设一个整稿策略 owner，评审者不要覆盖制作 peer 的策略。多个独立制作任务必须使用各自策略作用域。

## 冻结验收范围，避免越修越多

第一次整稿评审时，将问题分成：

| 类别 | 判断依据 | 处理 |
|---|---|---|
| 必修 | 违背用户要求；错漏文字或数据；不可编辑/文件损坏；实际阅读尺寸下遮挡、截断、错误归属、错误图文关系；未核实的产品外形修补 | 保留为 open/unknown，修好并用当前实际渲染复核 |
| 可选微调 | 不影响正确性、阅读或明确设计约定的细小留白/边距差异、个人风格偏好 | 写入 backlog；不单独发起新的返修轮次 |

严重性依据影响判断，不按页号或固定像素阈值判定。不能为了退出把真实错位降成可选，也不能在检查通过后临时追加审美偏好。新发现的必修缺陷与回归仍须处理，记录发现原因；新可选项不重置原缺陷的停滞历史。缺少必要检查是 unknown，不是 pass。

对必修项保留稳定 ID、影响、当前证据、最近修法、通过条件与连续无改善次数。无需给每个文本框建台账；同一原因可以分组，但不能用改名称、换 peer 或另起任务清掉历史。内核现有四类聚合计数不能代替协调者对同一缺陷的判断。

## 每轮修复与复核

1. 制作者批量处理一组同原因缺陷，复用公共工具；不要每挪一个字就重跑整稿。每个已完成的“改稿—渲染—检查”周期都记录证据，不能只把最后交回评审者的次数当作总修复次数。相同输入的轮询或重复记录不计新周期。
2. 交回确切 PPTX、对应实际渲染、改动范围和未解决项。评审者先看全页，再看有上下文的局部图；复用未改页面的有效证据，最终整稿再扫一遍。
3. 评审者独立检验通过条件。检查一个图形的完整边界、基线和所有重复元素；不能只统计一侧刻度、仅核对文字内容或只看模型圈出的区域。工具误报需说明证据，不篡改阈值换取通过。
4. 反馈发给同一个 peer，包含实际观察、影响及验收条件，不交付未经验证的坐标或代码。重开一个 peer 不等于提出了新的修法。
5. 外部作业 pending 时保留真实 job ID，等完成事件或有界查询；等待本身不算修复失败，不重复提交，不靠不断催促制造进度。

## 退出标准

| 状态 | 条件 | 行动 |
|---|---|---|
| 完成 | 必修项全部关闭，必要检查无 unknown，最终文件与受检稿一致，实际整稿复核通过 | 交付；可选微调列出即可，不为它们重开一轮 |
| 需要重规划 | 同一必修问题连续 3 个完整检查周期没有实质改善，或反复在几种错误间来回 | 停止原修法，保留产物与证据，诊断不同原因；没有可执行的新假设就交回未完成结果 |
| 诊断后仍停滞 | 一次不同原因的诊断/修复检查仍未改善，或收到宿主的 `needs_replan` yield | 制作 peer 交回；协调者不能只发“继续”，不能换名字重启以绕过退出 |
| 真实阻塞 | 必需素材、权限、配额或工具故障，且当前没有可行的已授权替代路径 | 报告具体依赖、错误与已有成果；不把阻塞称完成 |
| 预算达到 | 用户/宿主给定的时间、费用或运行预算用尽 | 停止派新任务，按宿主取消/收尾机制交回当前稿和未完成项，不擅自续费或扩大预算 |

“实质改善”须是该缺陷在同一通过条件下可观察地减轻或消失，且没有同等/更严重回归。工具调用增加、输出新文件、改检查框、关闭另一个可选项，不算该缺陷的改善。一个全新诊断可以改变方法，不能改验收标准或抹去累计记录。

3 是默认停滞诊断窗口，不是最多三轮，也不是任意时间内必然结束的保证；用户的明确窗口优先。未给总预算时不能捏造一个，但必须执行上述验收退出与停滞交回。技能约定由模型执行；内核只能强制其实际支持且已接通的部分，不能宣称技能文字本身构成硬性截止。

退出时简要报告：状态、当前 PPTX/预览、已关闭与未解决的必修项、实际检查范围、总修复周期/评审轮数，以及可得的耗时/费用。停止执行不等于通过验收。
