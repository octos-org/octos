# 成对设计、原生叠字与确定性导出

下文 `scripts/` 路径相对于本 skill 目录。实际执行时将脚本路径展开为绝对路径，项目文件参数使用当前项目的实际位置。使用已有项目虚拟环境，按需准备 Pillow、python-pptx、lxml；渲染检查另需 PyMuPDF 和 NumPy，不要求改动系统 Python。

## 从文稿到完整设计

用户指定 image-first 或沿用整页海报美学时，先得到可供重建的完整设计。提示词以**整张幻灯片**为设计单位：包含画布比例、主论点、具体对象与关系、精确标签、文字归属和阅读顺序，以及参考中的线条、尺度和信息密度。方形局部插图的“no text”提示词只定义一个素材，不能代替整页提示词。

让图承担具体解释：例如架构中的层与数据流、流程中的依赖与反馈、比较中的维度与差异。标签靠近其对象，数据附在相应的图表／关系上；把解释全部放进一侧长段落、另一侧仅放抽象装饰，不会因多生几张图而成为图文整合。不要为增加密度添加没有信息作用的图标或线条。

在扩大制作前，自主查看有代表性的完整设计页，核对图是否承载了论点、标签能否落位、密度是否符合参考；沿用 [视觉验收](visual-review.md) 的样稿方法。独立插画可以作为素材，但需要在完整页面中验收。随后从被接受的整页设计定向去字，保留图形与文字空间，再叠原生文字；原生文字以原文为准，不能照抄生成器的错字。

若用户要求先整页生图，把一个已经做好的简单 PPTX 去掉文字并渲染为背景，只是把旧版式栅格化，不能替代所要求的设计阶段。此方法仍可用于用户要求的现有稿件分层转换。

有字设计与可编辑交付不是二选一：前者提供整页图文布局，后者用同源无字底稿及原生文字实现。去字后图形受损时，修复该素材或调整去字方式，并重新对照；不要为绕开这个问题改成独立无字插画再套固定版位。

预览、OCR 和坐标计算可以使用独立缩小副本；记录换算比例并保留原始图。排版画布大小不决定背景文件的像素大小，嵌入 PPTX 时优先使用完整分辨率的同源背景。用户要求的输出尺寸与生成器实际提供的尺寸分别记录。

## 内容及素材清单

每页保存稳定的 slide ID、标题、必需文案／标签、图中对象关系、必须保留的图、讲者备注、来源，以及视觉参考。数学式和表格数据来自确定性计算，不从生图或 OCR 猜测。

项目可沿用已有目录；新项目通常采用：

```text
deck/
  source/          文稿、数据、可复现脚本
  prompts/         实际发送的生成／编辑提示词
  pairs/           生成器返回的原始全稿／底稿成对设计
  backgrounds/     裁出的无字背景
  layouts/         已审阅的原生文字位置与样式
  exports/         母版导出的 full、blank、paired
  verification/    尺寸、内容、字体、UX 与交付检查
```

## 生成分辨率与提示词

16:9 幻灯片的上下双联图，其整张比例为 8:9。比例不能被误写成固定的低分辨率画布。

示例约束：

```text
Generate one paired design: two equal 16:9 panels stacked vertically,
whole-sheet aspect ratio 8:9. Top: the labeled design. Bottom: the same
illustration with every label removed and the label spaces preserved.
Use the highest suitable output resolution actually supported by the tool.
Match the supplied reference's line weight, object scale, restrained depth,
light, typography hierarchy and diagram semantics.
```

补充该页的精确文案、结构和适合该页类型的参考图；不要用模板词代替设计。使用工具可配置的分辨率字段时核对其能力；提示词中的“4K”本身不能保证生成器按此尺寸返回。

用户要求原生 4K 每页背景时，单页应有至少 3840×2160 的实际生成像素；上下双联图相应需要约 3840×4320，且每个实际面板均满足。以最终裁出面板为准，不用整张双联图的像素数冒充一页分辨率。

工具无法达到要求时，记录限制，继续完成不依赖该能力的工作；不要擅自把插值放大描述为已达到原生分辨率。分块生成须验证接缝、比例、光照与语义，且如实记录组装方式，不默认实施复杂拼接。

如果一次双联生成导致细节明显不足或上下图结构漂移，可用高分辨率完整设计加定向编辑取得无字版本，再制作最终成对交付；尊重用户对“同一请求双联生成”的明确要求。任何路径都必须共享最终唯一的视觉背景。

保存实际源尺寸、面板裁切矩形、面板尺寸、生成／编辑方式和最终输出尺寸。可运行：

```sh
python scripts/inspect_rasters.py pairs/*.png --target 3840x4320 --out verification/pair-dimensions.json
python scripts/inspect_rasters.py raw-blank/*.png --target 3840x2160 --out verification/panel-dimensions.json
```

此脚本只读真实文件尺寸并计算缩放比例，不能判断已被预先放大的文件是否原生；须结合生成记录。Lanczos 放大改善重采样表现，不生成可信的新绘画细节。

## 裁切与配准

- 检查实际分隔线、外框和上下比例，不假定必然 `height // 2`。
- 每个面板独立记录 `(left, top, right, bottom)`。裁切图中不能残留标题、分隔线、页脚或伪文字。
- 视觉特征匹配只用于辅助估计位移／缩放；低匹配数、过度偏移、非等比缩放和旋转都需要复核。
- 分别按上下图真实宽高归一化。面板高度不同却使用同一高度，会导致底稿与文字系统性错位。
- 尽量保持纵横比和主要对象的位置。配准不能修复图形语义变化；明显变形时修正素材。
- 查看整张无字面板并做 OCR 辅助检查。零 OCR 检出不是绝对无字证明，图标中的伪文字仍需目视判断。
- 使用前对照有字设计检查去字是否改变了连接线端点、箭头方向、分支、圆点数量、图标或标签留白。全稿和派生无字 PPTX 图形层一致，只证明两份文件用了同一底图；不能证明底图忠实于原设计。按 [三项独立核对](review-evidence.md) 记录有意义的变化，在共享素材阶段处理，不把上游问题全部归给叠字模型。

## 原生文字与字体

以文稿为内容权威，以有字图辅助定位。每个文本对象保留 ID、全文、位置、大小、字体、颜色和对齐；适合时保存来源标签 ID，以便逐项比较。

OCR 常漏公式末尾变量、除号、短词、单字符和重复数值。必须单独核对：分子／分母、正负号、上下标、百分比、单位、表头、坐标、图例及全部数据点。出现两次的 50% 不能因只找到一次而算完整。

按用户指定字体与语言拆分 runs。CJK 字体回退要显式设置并检查真实渲染。优先静态常规字体或渲染器可靠支持的字形，不用伪加粗掩盖字体缺失。

先调整图文面积、分组与行长，再考虑缩字。正文与脚注的下限由实际演示用途判断；密集总览可以单独处理。紧贴文字的小底色可偶尔保护标签，不应系统性用白块遮盖错误构图。

## 母版与无字派生稿

python-pptx、PptxGenJS 或合适的原生工具均可。单页包含独立视觉层和文字层；本工作流建议：

- 图像／图形对象名以 `VISUAL__` 开头。
- 所有需在无字版本移除的独立文本框以 `TEXT__` 开头。
- 标签不要写进保留的图形对象。否则删除文字对象会连带删除图形，应先拆分对象。
- 讲者备注保留来源、解释及事实边界，不参与无字幻灯片的画面。

可用下面的辅助脚本派生无字稿并验证视觉对象不变：

```sh
python scripts/paired_deck.py blank master.pptx blank.pptx
python scripts/paired_deck.py check master.pptx blank.pptx --out verification/layers.json
```

脚本限于已明确分层并采用命名约定的 PPTX；不会把任意已有演示稿自动转换成完整可编辑结构。检测到未标记的文字或文本与图形混合时，应调整布局，不盲目删除。

## 导出与验证

用可用渲染器导出全稿和无字稿 PDF，记录实际工具与版本。用 PyMuPDF 等按用户要求的像素尺寸导出；最终成对图由这两个导出结果拼接。不要把生成器有字上半图冒充原生 PPTX 的最终渲染。

headless 工具可能在输入失败时仍返回退出码 0：检查预期 PDF 是否新生成、页数是否正确，不能仅依据进程退出码继续打包。

`scripts/paired_deck.py check` 可以附加渲染检查：

```sh
python scripts/paired_deck.py check master.pptx blank.pptx \
  --full-pdf render/full.pdf --blank-pdf render/blank.pdf \
  --render-size 3840x2160 --out verification/technical.json
```

检查母版和派生稿页数、非文本对象 XML／图片字节的一致性、无字稿残留文本、有字 PDF 文本可提取性，以及文本框外的像素差异。脚本明确的技术通过不证明源文案全部正确，也不证明美术质量。

另行核对：

- 原文标签与文本对象的一对一或显式分片映射，尤其重复值的数量及位置。
- PDF 字体实际嵌入／回退、显示边界、行距、小字、图表准确性。
- 无字位图中的残留文字；PDF 无文本只说明没有可提取文字。
- 与参考同标准的 UX 评审；详见 [visual-review.md](visual-review.md)。

最后检查 PPTX／ZIP 可读取、页数／图片数量、输出尺寸、文件链接和哈希清单。最终修改之后更新导出与检查结果，避免报告对应上一版文件。
